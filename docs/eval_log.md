# Evaluation log

Running record of every experiment run for the iteration loop described in
`docs/roadmap.md`. One row per run. Numbers only — if you want the reasoning
behind a change, that's in `roadmap.md` or the relevant commit, not here.

Metrics follow spec §8.2: Recall@1/5/10, MRR, median/mean rank. Caption
retrieval runs (SigLIP2) also report num_candidate_captions since R@5/R@10
are only meaningful relative to how many candidates exist.

Diagnosed by inspecting real mismatches (not guessing): merging silver/gray/cream/black into one tolerant "neutral family" for evaluation purposes alone jumped the match rate to 65.0%, showing nearly half the apparent errors were boundary confusion within the near-neutral spectrum (shadows/highlights on white or gray garments landing just past the silver/gray boundary), not real color-family mistakes.
- `build_color_index.py` pixel-color pipeline, **v2 (real fix, not a validation tolerance)**: merged "silver" into "gray" as one canonical bucket everywhere — `build_color_hierarchy.py`'s text-side mapping *and* `build_color_index.py`'s pixel-side reference swatches (20 canonical colors now, was 21) — since average-pixel-color extraction can't distinguish true metallic sheen (needs specular highlight info) from a shadowed neutral gray in the first place, so the extra bucket was pure boundary noise. Re-validated after the change, same methodology as before: primary match **39.2% → 46.4%**, primary-or-secondary **56.1% → 64.8%**. Real, measured improvement, not the evaluation-tolerance trick used to diagnose it.
